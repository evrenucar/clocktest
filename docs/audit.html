1Slider CSS never applies in any browserfix

One unrecognized selector invalidates the entire group. Chrome drops the rule (doesn't know -moz-), Firefox drops it (doesn't know -webkit-). The rainbow track and the colored thumb render in no browser at all.

2playMinuteChirp leaks a synth every minutefix
script.js:312

Allocates a Tone.Synth, never disposes it. The comment on tickSynth at line 39 names this exact failure mode — "memory buildup and audio stuttering". Hourly and quarter chirps both dispose correctly; this one doesn't. 1440 leaked synths/day.

Fix: hoist to a module-level synth like tickSynth, or dispose after ~500ms.

4Tick scheduler driftsfix
script.js:525 (local) and origin/main

Local computes delay from a timestamp taken before updateProgress() runs. origin/main replaced the whole thing with setInterval(1000), which accumulates drift and gets throttled in background tabs. Both walk off the second boundary — the opposite of what the commits titled "Fix clock running issue" intended.

const tick = () => { updateProgress(); setTimeout(tick, 1000 - Date.now() % 1000); };
tick();

2 lines replacing 9. Re-anchors to the wall clock on every tick.

5Skipped seconds silently drop chimesdeferred
script.js:364-376

The lastHourPlayed / lastQuarterPlayed / lastMinutePlayed guards suppress a double fire but cannot recover a skipped second. If the tab is throttled past seconds === 0, the hourly chime is lost with no trace.

Mostly downstream of #4. A backgrounded tab can't meaningfully chime anyway — leaving it.

6Tick-tock has no second-dedupedissolves into #4
script.js:379

Plays on every updateProgress call, unlike the other three sounds which all check a last*Played guard. A double-fire is an audible double tick — this is the reported "stutter".

Fixing #4 guarantees exactly one fire per second boundary, so no separate guard is needed.
